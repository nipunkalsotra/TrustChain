# TrustChain demo transcript

Recorded locally using real model/search services and Anvil chain evidence. Narration is synthetic.

## 0s — TrustChain — verifiable AI from task to independent evidence

Welcome to TrustChain. This live local recording uses real model and web search calls, and blockchain evidence on Anvil. We will follow a task, its scores, and its verifiable audit trail.

## 16s — 1 · Create a real account and project workspace

We create a disposable account. TrustChain provisions an organization and project. Verification email is captured by the local console backend; external email delivery is not part of this recording.

## 34s — 2 · Follow the actual verification email link

The actual emailed link opens the verification page and consumes a single use token. Verified accounts can create scoped integration keys and invite teammates.

## 50s — 3 · Runs, identities, scores, and evidence in one workspace

The dashboard brings together runs, agent identities, scores, audit evidence, and integrity alerts. Projects separate activity and integration credentials. This new workspace starts empty.

## 66s — 4 · Launch a real four-agent research workflow

We submit a real task. The built in workflow moves through researcher, validator, scorer, and reporter. The browser follows persisted activity as the agents work.

## 82s — 5 · Live research, fact-checking, scoring, and report generation

The agents call the configured model and search services. Each action creates a durable step. A worker groups steps into Merkle batches and submits their roots on chain. Confirmation is asynchronous and visible in the trail.

## 122s — 6 · Inspect the report and all four agent scores

The report is the final workflow output. Scores summarize observed pipeline quality; they do not guarantee factual correctness. The scores page compares the four agents using indexed results from this run.

## 138s — 7 · Follow agent activity to confirmed chain transactions

The audit trail shows what each agent did and links actions to evidence. We wait for all steps to confirm. The anchors page groups those steps by transaction and identifies the evidence chain.

## 154s — 8 · Retrieve a Merkle proof and verify the run

A step proof contains its leaf, root, sibling path, and confirmed transaction. The verification studio checks the complete run against its recorded evidence, connecting readable activity to cryptographic integrity.

## 172s — 9 · Connect an external agent through the real SDK

We create a scoped key and register an external agent with the TypeScript SDK. Its activity enters the same audit trail. Configuration hashes are sent instead of raw system prompts. This disposable key is revoked before the demo ends.

## 194s — 10 · Verify identity and detect configuration drift

The registry binds a configuration fingerprint to an on chain identity. We inspect and verify it. A step logged using a different fingerprint produces an integrity alert, which we will investigate next.

## 212s — 11 · Investigate and resolve a genuine integrity finding

This finding was generated by the mismatched SDK fingerprint. An administrator can inspect the evidence, add an investigation note, and resolve it. Detection becomes an accountable investigation workflow.

## 230s — 12 · Team access, persistent preferences, and key revocation

The workspace includes teammate invitations and role based access. Settings manage projects and notifications. Preferences persist on the backend, and integrations lose access when their key is revoked.

## 248s — TrustChain · task → agents → scores → evidence → verification

We followed a real task through the pipeline, report, scores, confirmed chain evidence, and verification. We connected an SDK agent and investigated identity drift. The accompanying report records the test results and the limits of this local demonstration.
